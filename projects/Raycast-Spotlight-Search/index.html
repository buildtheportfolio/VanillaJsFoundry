Helix / Documentation

Introduction to Helix

Helix is a battle-tested design system built for product teams who ship fast without sacrificing quality. It provides a comprehensive set of accessible, themeable components backed by a robust token architecture.

This documentation covers everything from initial setup to advanced customization patterns, including our accessibility guidelines, performance best practices, and the complete component API reference.

New in v2.4: Dark mode support, RTL layouts, and the new Figma Variables integration. See the changelog →

Installation

Install Helix via your preferred package manager. The core package includes all components, tokens, and utilities. 

npm install @helix/core @helix/icons
# or
yarn add @helix/core @helix/icons
# or
pnpm add @helix/core @helix/icons

Peer Dependencies

Helix requires React 18+ and TypeScript 5+. For Vue users, see the Vue Adapter docs.

CDN Usage

For rapid prototyping, you can load Helix directly from our CDN at cdn.helix.design.

Quick Start

Wrap your application with the HelixProvider to enable theming and global configuration. 

import { HelixProvider } from '@helix/core';

function App() {
  return (
    <HelixProvider theme="dark" locale="en-US">
      <YourApp />
    </HelixProvider>
  );
}

First Component

Import components directly from the core package. Tree-shaking is supported out of the box.

TypeScript Support

Helix ships with full TypeScript definitions. No @types package is needed.

Design Tokens

Design tokens are the single source of truth for visual decisions in Helix. They map to CSS custom properties at runtime, enabling seamless theming.

Token Architecture

Tokens are organized in three tiers: Primitive (raw values), Semantic (contextual meanings), and Component (per-component overrides).

Token Categories

Available token categories include: colors, typography, spacing, border-radius, shadows, motion, and z-index scales.

Customizing Tokens

Override tokens at the HelixProvider level or via CSS custom properties in your global stylesheet.

Breaking change in v2.x: Token naming convention changed from --hx-color-* to --hx-*. Use the codemod to migrate automatically.

Typography

Helix uses a modular type scale built on CSS custom properties. The default scale is based on the perfect fourth ratio (1.333).

Type Scale

The scale runs from --hx-text-xs (11px) through --hx-text-6xl (64px) with corresponding line-height and letter-spacing values for each step.

Font Stack

The default font stack uses system fonts for optimal performance: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica Neue, Arial, sans-serif.

Responsive Typography

Use the fluid() utility to create fluid type scales that interpolate between viewport breakpoints.

Color System

The Helix color system is built around perceptual uniformity using the OKLCH color space, ensuring accessible contrast at every step of each scale.

Color Scales

Each color family provides 12 steps: 1-3 for backgrounds, 4-6 for borders, 7-9 for solid fills, 10-12 for text. This maps directly to WCAG contrast requirements.

Semantic Color Tokens

Semantic tokens like --hx-color-primary, --hx-color-danger, and --hx-color-success adapt automatically between light and dark modes.

Dark Mode

Enable dark mode by setting data-theme="dark" on the root element, or let HelixProvider detect the system preference automatically.

Accessible Color Pairs

Use the getContrastColor() utility to automatically select the highest-contrast foreground for any background color in the palette.

Buttons

The Button component supports five variants: primary, secondary, ghost, destructive, and link. All variants are keyboard-accessible and respect the system's reduced-motion preference.

Button Sizes

Available sizes: xs, sm, md (default), lg, xl. Size affects padding, font-size, and min-touch-target area.

Icon Buttons

Use IconButton for icon-only actions. Always provide an aria-label for accessibility.

Loading State

Pass loading={true} to show a spinner and disable the button. The accessible name changes to "Loading…" automatically.

Button Groups

Compose buttons in ButtonGroup to create segmented controls and action toolbars with connected borders.

Form Elements

Helix provides a complete set of accessible form controls: Input, Textarea, Select, Checkbox, Radio, Switch, Slider, and DatePicker.

Form Validation

Integration with React Hook Form and Zod is built-in. Use the FormField wrapper for automatic error state, aria attributes, and label association.

Controlled vs Uncontrolled

All form components support both controlled and uncontrolled modes. For most use cases, the controlled mode with React Hook Form is recommended.

Accessibility in Forms

Every form element automatically generates a unique ID, links to its label, and announces validation errors via aria-describedby.

Accessibility Guide

Helix is built to WCAG 2.1 Level AA compliance. Every component ships with correct ARIA roles, keyboard navigation, focus management, and screen reader support.

Keyboard Navigation

All interactive components follow the ARIA Authoring Practices Guide (APG). Tab order is logical, and complex widgets like menus and dialogs implement roving tabindex.

Focus Management

Modals, drawers, and popovers trap focus within their boundaries and restore focus to the trigger element on close.

Screen Reader Support

All interactive state changes are announced via live regions. Dynamic content updates use aria-live="polite" for non-critical and aria-live="assertive" for critical announcements.

Reduced Motion

All animations respect prefers-reduced-motion. Critical animations are removed; decorative animations are simplified to fades.

Color Contrast

All default color combinations meet WCAG 2.1 AA (4.5:1 for normal text, 3:1 for large text and UI components).

Performance Tips

Helix is optimized for performance with tree-shaking, code-splitting, and zero runtime CSS-in-JS overhead.

Bundle Size

Import only the components you use. The full library is 42KB gzipped, but a typical app uses 8–15KB.

CSS Performance

Helix uses CSS custom properties for theming instead of runtime style injection, eliminating FOUC and improving paint performance.

Virtualization

For large lists and tables, use VirtualTable and VirtualList which render only visible rows using the intersection observer.

Server Side Rendering

All components support SSR and streaming SSR with React 18's renderToPipeableStream. No hydration mismatches.

Contributing

We welcome contributions from the community. Helix follows conventional commits, requires tests for all components, and uses Storybook for visual development.

Development Setup

Clone the monorepo, run pnpm install, then pnpm dev to start Storybook. All packages live in the /packages directory.

Pull Request Process

PRs require passing CI, a changelog entry, and design review for visual changes. Component PRs need Storybook stories and accessibility audits.

Issue Reporting

Use GitHub Issues for bugs, feature requests, and accessibility reports. Include a minimal reproduction for bugs using our StackBlitz template.
