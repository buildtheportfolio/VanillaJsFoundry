# Vanilla JS Foundry

A hub for small, self-contained Vanilla JavaScript projects built with **HTML + CSS + JavaScript**.

> Every project follows the three-file contract: `index.html` · `style.css` · `script.js`.
>
> **No frameworks, no runtime dependencies, no build step needed to serve the site.** TensorFlow.js is the one exception, for AI/ML projects only.

**Live site:** `https://<your-github-username>.github.io/<this-repository-name>/` (replace with your own once Pages is enabled; nothing in the code depends on these names).

## Project structure

```text
VanillaJsFoundry/
├── index.html  style.css  script.js     # the hub
├── projects.json                        # generated by scripts/build-projects.mjs
├── 404.html  .nojekyll
├── scripts/
│   ├── build-projects.mjs               # scans projects/*/ -> projects.json
│   └── validate.mjs                     # contract checks (CI fails on error)
├── .github/workflows/pages.yml          # build + validate + deploy to Pages
├── Ideas/README.md
└── projects/
    ├── _template/                       # copy this to start a project
    └── <Name>/{index.html,style.css,script.js}
```

## Add a project

1. Copy `projects/_template/` to `projects/<Your-Name>/` (the folder name is the route).
2. Build it using only `index.html`, `style.css` and `script.js` (assets, if any, must live inside the folder).
3. In `index.html` set `<title>`, `<meta name="description">`, and the hub metadata:
   ```html
   <meta name="foundry:category" content="Games">
   <meta name="foundry:difficulty" content="Beginner"> <!-- Beginner | Intermediate | Advanced -->
   <meta name="foundry:tags" content="canvas,keyboard,arcade">
   ```
4. Use relative paths only (no leading `/`), keep the `← Foundry` back link, the `<noscript>` notice and the favicon from the template.
5. Run `node scripts/build-projects.mjs && node scripts/validate.mjs` locally, then push. No hub code needs editing.

## Project contract (enforced by `scripts/validate.mjs`)

- `index.html`, `style.css`, `script.js` all present; `script.js` has no syntax errors.
- `<title>`, `<meta name="description">`, `<html lang>`, a `../../` back link, a `<noscript>` notice, an icon link.
- `prefers-reduced-motion` and `:focus-visible` rules in `style.css`.
- No absolute `/` asset paths, no hardcoded repository owner/name, no duplicated `script.js`.

Folders without all three files are ignored by the hub. `_template` is never listed.

## Run locally

```bash
node scripts/build-projects.mjs      # regenerate projects.json
python -m http.server 8080           # or any static server, then open http://localhost:8080/
```

Opening `index.html` via `file://` will not work because the hub fetches `projects.json`.

## GitHub Pages setup

1. Push the repository to GitHub (default branch `main`).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Push to `main`. The workflow `.github/workflows/pages.yml` regenerates `projects.json`, runs the validation, and deploys.
4. The site appears at `https://<user>.github.io/<repo>/`. Everything is relative, so it works under that sub-path.

## Design rules

- One project = one directory = three files.
- Never edit a central registry; the hub discovers projects from `projects.json`.
- Keep projects independent so one cannot break another.
- Escape or `textContent` anything that comes from users or APIs; never raw `innerHTML` with external data.
- Guard `localStorage` access with `try/catch`.
- Browser and platform APIs are encouraged; TensorFlow.js only for AI/ML projects.
